How it works

The monitor asks your FortiGate every few seconds for the results of its SD-WAN Performance SLA (health check): latency, jitter, packet loss and whether probes succeed, measured separately on each WAN link. It also reads each interface's physical link state and traffic counters.

Each link is classified as HEALTHY WARNING CRITICAL or DOWN. A problem must persist for several polls before you are alerted (so a single lost probe does not wake you up), and every alert says what the other link is doing, so you know immediately whether you are running on one link or have lost internet completely.

Why the FortiGate and not pings from this PC? Pings from this PC leave through whichever link the FortiGate load-balances them to, so they cannot tell WAN1 and WAN2 apart. The FortiGate's health check probes each link individually.

Requirements

FortiGate

  • FortiOS 6.4 or later (7.0 – 7.6 recommended).
  • SD-WAN enabled with both WAN interfaces as SD-WAN members. Two plain static default routes (ECMP) without SD-WAN are not supported, because there is no per-link health data to read.
  • A Performance SLA (health check) that includes both WAN interfaces. The built-in Default_DNS works if both links are members.
  • A REST API administrator with a read-only profile (System and Network: Read) and this server's IP as a trusted host.
  • HTTPS administrative access enabled on the FortiGate interface this server connects to (usually the LAN interface), and the admin HTTPS port (default 443).
  • If VDOMs are enabled: the name of the VDOM that holds the SD-WAN configuration.

Monitoring server

  • An always-on machine on the LAN: Windows 10/11 or Windows Server 2016+ (Linux and macOS also work).
  • Node.js 22.13 or newer (Node 24 LTS recommended). No other software and no npm install needed.
  • A fixed IP address, because the FortiGate's trusted-host setting and the optional webhook point at it.
  • About 100 MB of disk space for 14 days of history.

Install on Windows

On the always-on PC that will run the monitor:

  1. Download the project from GitHub (Code > Download ZIP) or copy the package you received, and extract it.
  2. Double-click Install.cmd and approve the Windows UAC prompt (the only prompt).
  3. The installer downloads and silently installs Node.js LTS if needed (checksum and signature verified), installs the monitor to C:\Program Files\FortiGate WAN Monitor, keeps its data in C:\ProgramData\FortiGate WAN Monitor (Administrators only), opens the firewall port, and starts it as a background task that runs at boot.
  4. When it finishes, open this guide and continue with Connect to your FortiGate.

Re-running Install.cmd upgrades the monitor and keeps all settings and history. Full options (unattended deployment, proxy, offline install, custom port) are in the project README under Deployment guide.

Admin command (Administrator prompt)What it does
wanmon.cmd statusShows whether the background task is running
wanmon.cmd restart / stop / startControls the monitor
wanmon.cmd logsFollows the log file
wanmon.cmd --set-passwordSets the dashboard password (then restart)

wanmon.cmd is in C:\Program Files\FortiGate WAN Monitor. To remove the monitor, double-click Uninstall.cmd in the extracted folder.

Connect to your FortiGate

Checking current connection…

Step 1 · Confirm SD-WAN and the health check

In the FortiGate CLI run the command below. You should see a health check listing both WAN interfaces with state(alive). Note the health check name and the exact interface names.

diagnose sys sdwan health-check

If there is no health check that contains both links, create one (GUI: Network > SD-WAN > Performance SLAs > Create New) or use the CLI. Replace 1 2 with your members' sequence numbers (see show system sdwan):

config system sdwan
    config health-check
        edit "WAN_SLA"
            set server "8.8.8.8" "1.1.1.1"
            set protocol ping
            set interval 500
            set failtime 3
            set recoverytime 5
            set members 1 2
            set update-static-route enable
            config sla
                edit 1
                    set latency-threshold 150
                    set jitter-threshold 30
                    set packetloss-threshold 2
                next
            end
        next
    end
end

Step 2 · Allow HTTPS admin access from this server

On the interface this server reaches the FortiGate through (GUI: Network > Interfaces > edit > Administrative Access: HTTPS):

config system interface
    edit "internal"          # your LAN interface name
        append allowaccess https
    next
end
get system global | grep admin-sport    # shows the HTTPS admin port (default 443)

Step 3 · Create a read-only admin profile

GUI: System > Admin Profiles > Create New, name wanmon-readonly, set System and Network to Read, everything else to None. Or in the CLI:

config system accprofile
    edit "wanmon-readonly"
        set sysgrp read
        set netgrp read
    next
end

Step 4 · Create the REST API administrator and key

GUI: System > Administrators > Create New > REST API Admin. Username wanmon, profile wanmon-readonly, and under Trusted Hosts enter only this server's address: 192.168.1.50/32. Click OK and copy the API key immediately; it is shown only once.

Or in the CLI:

config system api-user
    edit "wanmon"
        set accprofile "wanmon-readonly"
        set vdom "root"
        config trusthost
            edit 1
                set ipv4-trusthost 192.168.1.50 255.255.255.255
            next
        end
    next
end
execute api-user generate-key wanmon
Treat the key like a password. The profile is read-only, so the monitor can never change your FortiGate's configuration.

Step 5 · (Optional) test from this server

In PowerShell on this server. A JSON reply listing your health check means the FortiGate side is ready:

curl.exe -k -H "Authorization: Bearer <API-KEY>" "https://192.168.1.1/api/v2/monitor/virtual-wan/health-check?vdom=root"

Step 6 · Enter the details in the monitor

Open ⚙️ Settings & Alerts > FortiGate API on the dashboard and fill in:

FieldValue
FortiGate Admin Host / URLhttps://<FortiGate IP>, or https://<IP>:<port> if the admin port is not 443
REST API Administrator TokenThe key from step 4
WAN 1 / WAN 2 Interface NameExactly as shown on the FortiGate, e.g. wan1, port1, x1 (currently wan1 and wan2)
SD-WAN Health Check NameFrom step 1 (currently Default_DNS)
Display names / Site nameFriendly names used in alerts, e.g. "MTN Fibre", "Head Office"

Click Test FortiGate Connection. It lists the health checks the FortiGate reports and warns if an interface is not a member. Then click Save Changes.

Step 7 · Switch off simulation

Make sure Simulate WAN Traffic on the dashboard is off. Within a few seconds both link cards should show real latency and loss, and the top bar should read FortiGate: Online.

Real-time webhook (optional)

Polling already detects every problem. The webhook additionally forwards the FortiGate's own SD-WAN events the moment they happen. It is authenticated with a secret token.

Your webhook URL (contains the token, keep it private):

http://<this-server>:4000/api/webhook/fortigate?token=<see Settings > FortiGate API>

Create the Automation Stitch

  1. GUI: Security Fabric > Automation > Create New (on some versions: Stitch).
  2. Trigger: FortiOS Event Log. Add the SD-WAN health-check / SLA status events (type "SD-WAN" in the event search).
  3. Action: Webhook. Protocol and URL as above, method POST, header Content-Type: application/json, body: 
    {"log": "%%log%%"}
  4. Save, then unplug a WAN cable briefly or use Test Automation Stitch. The event appears as an alert on the dashboard.

Event names and menu locations differ slightly between FortiOS versions.

Remote access & security

  • Until a password is set, the dashboard works only on this server (http://localhost:4000). To open it from other PCs, open an Administrator command prompt on the server and run: 
    "C:\Program Files\FortiGate WAN Monitor\wanmon.cmd" --set-password
"C:\Program Files\FortiGate WAN Monitor\wanmon.cmd" restart
    Sign in as user admin with that password. (You can also set it during installation with Install.cmd -PromptForPassword. When running from a folder instead of the installer, use node server.js --set-password.)
  • The FortiGate webhook uses its own token and does not need the dashboard password.
  • Secrets (API token, SMTP password, bot tokens, webhook URLs) are never sent back to the browser in full.
  • Keep the FortiGate API profile read-only and restrict its trusted host to this server.

Alerts & notification channels

Configure channels under ⚙️ Settings & Alerts > Notifications & Alerts and use each channel's Test button. You are notified when a link degrades, goes down, gets worse, and recovers; with a reminder every 30 minutes (configurable) while it stays bad; and if the monitor loses contact with the FortiGate.

If both links go down nothing can reach the internet, including your alerts. They are queued and delivered as soon as a link returns, marked as delayed with the original time.
  • Telegram: create a bot with @BotFather, send it a message, then read your chat ID from https://api.telegram.org/bot<TOKEN>/getUpdates.
  • Microsoft Teams: in the channel choose Workflows > "Post to a channel when a webhook request is received" and paste the URL.
  • Email (Microsoft 365): the sending mailbox needs Authenticated SMTP enabled; use smtp.office365.com, port 587.
  • Windows toast notifications are not visible while the monitor runs as the background service.

Daily reports

Click 📊 Reports on the dashboard to generate the report for any day still in the history (14 days by default). Each report shows, per link:

  • Availability (share of monitored time the link passed traffic), number of outages and total down time.
  • Time spent degraded (WARNING or CRITICAL).
  • Latency average / 95th percentile / maximum, packet loss and jitter.
  • How long the site had no internet at all (both links down) and how long it ran on a single link.
  • Every incident with start, end, duration and reason.

Open the full report in a new tab to print or save it as PDF, or download CSV for Excel. To receive it automatically, enable it under ⚙️ Settings & Alerts > Daily Reports and choose a time. Yesterday's report is sent every morning through all enabled channels (email gets the full report, chat channels a summary). Data coverage below 100% means the monitor was not running for part of the day.

Changing the port

Default port is 4000. Change it under ⚙️ Settings & Alerts > Server & 24/7 Service. The new port takes effect immediately and the dashboard reloads on it. Afterwards:

  • Update the FortiGate Automation Stitch webhook URL, if you use it.
  • On Windows the firewall rule is updated automatically when the monitor runs as the background service. Otherwise re-run the installer with the new port: Install.cmd -Port 5000 (settings and history are kept).
  • If the PORT environment variable is set, it takes precedence and the setting is locked.

Stop users being affected when a link fails

The monitor tells you about problems; these FortiGate settings stop users feeling them.

1. Let the health check remove a dead link

With set update-static-route enable (the default) on the health check from step 1, a link whose probes fail is taken out of the routing table within about interval × failtime (0.5 s × 3 = 1.5 s), so new sessions stop going to it.

2. Steer traffic by SLA, not just by link state

GUI: Network > SD-WAN > SD-WAN Rules. Use the strategy Lowest Cost (SLA) or Maximize Bandwidth (SLA) and select your health check, so traffic also moves away from a link that is up but degraded.

3. Move existing NAT sessions to the surviving link

By default, established NAT sessions keep using the failed link. This global setting makes them re-evaluate after a route change:

config system global
    set snat-route-change enable
end

4. Keep session stickiness off on WAN interfaces

set preserve-session-route enable on an interface keeps sessions on their original link while its route exists. Leave it disabled on the WAN members unless you need it for a specific reason.

5. Test

diagnose sys sdwan health-check
get router info routing-table all

Unplug one WAN: its route should disappear within seconds and browsing should continue on the other link.

Troubleshooting

Message or symptomCause and fix
HTTP 401, "rejected the API token"Wrong key, or this server's IP is not in the REST API admin's Trusted Hosts. Check the IP (NAT or VPN can change it) and regenerate the key if unsure.
HTTP 403, "denied access"The admin profile lacks Read on System/Network, or the API user is not assigned to the VDOM.
HTTP 404, "endpoint not found"SD-WAN is not enabled, the VDOM name is wrong, or FortiOS is older than 6.4.
Timed out / connection refusedWrong IP or admin port, HTTPS not allowed on that FortiGate interface, or a firewall in between. Open https://<FortiGate IP> in a browser on this server to check.
"No SD-WAN health-check data for …"The interface name does not match exactly, or the interface is not a member of the health check. Test FortiGate Connection lists the members it sees.
A link shows DOWN but it worksThe health-check target is unreachable over that ISP (e.g. ICMP blocked). Use another server or protocol (HTTP/DNS). On high-latency links (satellite, some LTE) raise the health check's probe-timeout above the normal latency.
"Remote access is disabled"No dashboard password yet. As Administrator run wanmon.cmd --set-password then wanmon.cmd restart (in C:\Program Files\FortiGate WAN Monitor).
No alerts arriveUse each channel's Test button; errors are shown there. For Microsoft 365 email, enable Authenticated SMTP for the mailbox.
Report coverage below 100%The monitor was stopped or the PC was off for part of the day. Install it with Install.cmd so it runs as a background service that starts with Windows.
