🛡️ FortiGate SD-WAN Tuning Guide: Prevent User Impact on Failover

Why do your users get disconnected when one WAN degrades?
By default, standard FortiGate ECMP (load balancing) continues hashing new and existing TCP connections onto a link as long as the physical interface is UP. Furthermore, ongoing TCP sessions freeze because NAT session tables are not forcibly reset. Apply these 5 optimizations to achieve sub-second zero-impact failover.

1. Enable Immediate Session Reset on SLA Failover (FortiOS CLI)

When WAN1 drops or degrades, this command immediately sends TCP RST packets to clients so web browsers, VPNs, and applications reconnect instantly via WAN2 without stalling for 30–60 seconds:

config system sdwan
    config service
        edit 1
            set name "Internet-Traffic"
            set service-reset enable
        next
    end
end

2. Enable SNAT Route Change on Session Failover

Ensures existing NATed traffic changes to the surviving WAN IP address automatically:

config system interface
    edit "wan1"
        set snat-route-change enable
    next
    edit "wan2"
        set snat-route-change enable
    next
end

3. Configure High-Sensitivity SD-WAN Performance SLA

Decrease the health check probe interval and failure count so degradation is declared in under 1.5 seconds instead of 30 seconds:

config system sdwan
    config health-check
        edit "Default_DNS"
            set server "8.8.8.8" "1.1.1.1"
            set interval 500       # Probe every 500ms
            set failtime 3         # Fail after 3 misses (1.5 seconds)
            set recoverytime 5     # Require 5 clean probes to recover
            config sla
                edit 1
                    set latency-threshold 120
                    set jitter-threshold 25
                    set packetloss-threshold 2
                next
            end
        next
    end
end

4. Change SD-WAN Rule Mode from Simple ECMP to "Lowest Cost (SLA)"

In GUI: Network > SD-WAN > SD-WAN Rules. Set strategy to Lowest Cost (SLA) or Maximize Bandwidth (SLA) with your SLA check selected. Traffic will never be forwarded to a degraded link.

5. Setup FortiGate Webhook to notify this App Instantly

Under Security Fabric > Automation > Create Stitch:

  • Trigger: FortiOS Event Log -> Event ID 0100022922 (SD-WAN SLA status change) or 0100022924.
  • Action: Webhook -> URL: http://<your-app-ip>:4000/api/webhook/fortigate
